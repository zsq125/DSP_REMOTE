## 一、为什么要做方案 A（背景，一句话）

手机 App → 网关（8765）→ **网关原来是"第二个 DSH 实例"（3099）**。
但 DSH 对会话实行**单写者**：会话若已被主 DSH（3080）持有写句柄，第二个实例 `resume` 它会返回
`session/writer-held` ⇒ **HTTP 409**。

**后果**：用户最想要的"用手机控制 PC 上**正在跑的任务**"恰好全部 409（那些会话正被 3080 占用）。

**方案 A**：把网关**挂进主 DSH（3080）进程内**，与 PC 端成为**同一个写入者** ⇒ 不再冲突。

## 四、重启后的验证（**必做**，逐项留证据）

```powershell
$tok = (Get-Content F:\project\deepseekharness_remote_control\pc-gateway\.state\token.txt -Raw).Trim()
$base = 'http://127.0.0.1:8765/rc/v1'

# V1. 网关卡是否由主 DSH 进程托管（关键！应能看到 8765 的 OwningProcess == 3080 的 pid）
(Get-NetTCPConnection -LocalPort 8765 -State Listen).OwningProcess
(Get-NetTCPConnection -LocalPort 3080 -State Listen).OwningProcess     # 两者应相同

# V2. 基本接口
Invoke-WebRequest "$base/status?token=$tok" -UseBasicParsing | Select-Object -Expand Content

# V3. 【核心】对"PC 正在用的会话"发消息 —— 方案 A 的意义就在这里，应不再 409
#     先找 PC 端开着的那个（例如 msgs 最大的主会话）
$s = (Invoke-WebRequest "$base/sessions?token=$tok&limit=100" -UseBasicParsing).Content | ConvertFrom-Json
$big = $s.items | Where-Object { -not $_.parentSessionId -and -not $_.isSubagent } | Sort-Object messageCount | Select-Object -Last 1
$big | Select-Object id, title, messageCount, status

$rid = [guid]::NewGuid().ToString()
Invoke-WebRequest "$base/sessions/$($big.id)/prompt?token=$tok" -Method POST `
  -Body (@{text='方案A验证：收到请回 pong';requestId=$rid} | ConvertTo-Json -Compress) `
  -ContentType 'application/json' -UseBasicParsing | Select-Object StatusCode, Content

# V4. 4 秒后查 status 必须变 running（这是"真的执行了"的客观判据）
Start-Sleep 4
((Invoke-WebRequest "$base/sessions?token=$tok&limit=100" -UseBasicParsing).Content | ConvertFrom-Json).items |
  Where-Object { $_.id -eq $big.id } | Select-Object status
```

**判据**：
- **V1 两个 pid 相同** ⇒ 网关确实跑在主 DSH 内（方案 A 成功的标志）
- **V3 返 200 而非 409** ⇒ 单写者冲突已解决
- **V4 变 running** ⇒ 消息真的被执行
