# 08 · 手机端 UI 重构与远程客户端需求（v1）

> 需求来源：用户 2026-10-11 明确指示
> 目标：App 界面与 DSH 电脑端一致（工作区 → 会话 → 对话），去掉一切多余控件；支持实时状态与发送对话

---

## 一、用户原话（需求基线）

1. 「界面我要做的跟 deepseekharness 电脑端的一样。我现在左侧显示几个工作区，工作区内几个会话，app 那里就应该显示几个，**其他多余控件统统不要**。」
2. 「需要跟 PC 一样**共享任务的实时状态**。」
3. 「实时状态具体要看到什么？……**会话是否在运行、最后一条消息、之前的对话记录、subagent 的对话记录**，并且**可以发送对话和实时对话**。」
4. 「**设置不要**。」（即移除设置页）
5. 二维码：见 §五。

---

## 二、目标界面（**左右分栏，同屏** —— 严格对齐 DSH 电脑端）

> ⚠️ **2026-10-12 用户纠偏**：此前实现的「三级跳转」（工作区→会话→详情一层层点进去）**不符合要求**，用户明确否决：
> 「界面完全不像 deepseek 的 app 版，**左边任务栏，右侧对话栏**」
> **必须改为同屏左右分栏，不得再用逐级跳转。**

```
┌──────────────────┬────────────────────────────────────┐
│  任务栏（左，窄）│  对话栏（右，宽）                   │
│                  │                                    │
│  ▾ 工作区 A      │   ┌──────────────────────────────┐ │
│     ● 会话 1     │   │ [消息流]                     │ │
│     ○ 会话 2     │   │   user（右）                 │ │
│  ▸ 工作区 B      │   │   assistant（左）            │ │
│  ▸ 工作区 C      │   │   [tool] name（折叠）        │ │
│  …（12 个）      │   │   …（向上滚动加载更早）      │ │
│                  │   └──────────────────────────────┘ │
│                  │   ┌──────────────────────────────┐ │
│                  │   │ 输入框            [发送]     │ │
│                  │   └──────────────────────────────┘ │
└──────────────────┴────────────────────────────────────┘
```

**布局硬要求**：

1. **同屏左右分栏** —— 左侧任务栏与右侧对话栏**同时可见**，**不是**逐级跳转页面。
2. **左侧任务栏**（窄栏）：
   - **两级树**：**工作区**（可折叠/展开）→ **其下会话**
   - 工作区行：标题 + 会话数
   - 会话行：标题 + **状态圆点**（运行中/空闲）+ 消息数（末条预览可选，窄栏放不下就省略）
   - **点击左侧任一会话** → **右侧立即切换**为该会话的对话（**不离开当前页**）
   - **默认展开当前会话所在的工作区**，并**高亮当前会话**
3. **右侧对话栏**（宽栏）：
   - 顶部：当前会话标题 + 状态
   - 中部：消息流（**历史 + 实时追加**），向上滚动加载更早
   - 底部：输入框 + **发送**（运行中时显示**停止**）
   - **未选中会话时**显示占位提示（如「从左侧选择一个会话」）
4. **窄屏适配**：手机竖屏下左栏宽度取 **约 1/3（≤ 38%）**，右栏占其余；**左栏可一键折叠/展开**（折叠后右栏全宽），折叠状态需记忆。
5. **状态**：左侧会话列表的状态圆点与右侧对话**实时同步**（WS 驱动）。

**移除项**（用户明确要求）：
- ❌ **三级跳转式导航**（本次纠偏的核心）
- ❌ 设置页
- ❌ 「共 N 个任务」「刷新」等冗余控件
- ❌ 手动配对输入框（配对只保留扫码 + 首次自动）

## 三、数据来源（PC 端实测确认）

### 3.1 已有 API（**全部已实现，无需改动**）

| 端点 | 用途 | 实测 |
|---|---|---|
| `GET /rc/v1/ping` | 健康检查 | ✓ 200 |
| `GET /rc/v1/status` | `{sessions:{total,running}}` | ✓ `total=112` |
| `GET /rc/v1/sessions?limit&cursor` | 会话列表 | ✓ 返回 50 条 |
| `GET /rc/v1/sessions/{id}/messages?limit&before&waitRequestId` | **对话记录** | ✓ 已实现 |
| `POST /rc/v1/sessions/{id}/prompt` | **发送消息**（幂等 requestId） | ✓ 已实现 |
| `POST /rc/v1/sessions/{id}/cancel` | 取消/停止 | ✓ 已实现 |
| `WS /rc/v1/stream` | **实时流** | ✓ 已实现 |

**会话列表项字段**（实测）：
```json
{
  "id": "session-00723a9e-…",
  "title": "需求：deepseekharness 手机端和电",
  "status": "idle",                       // idle | running
  "createdAt": 1791650832256,
  "updatedAt": 1791704109111,
  "cwd": "F:\\project\\deepseekharness_remote_control",   // ★ 工作区归属
  "messageCount": 520,
  "lastMessagePreview": "[tool] pwsh",
  "agentAvailable": false
}
```

### 3.2 需要新增：工作区 API

**PC 端工作区数据**：`~/.dsh/storages/workspace.json`
```json
{

    "workspaceIds": ["c6451375-…", "7e3bf619-…", …]   // 12 个，有序

**新增端点**：
```
GET /rc/v1/workspaces
→ { "v":1, "items":[ { "id":"<uuid>", "title":"craw_job",
                       "path":"F:\\project\\craw_job",
                       "sessionCount":2, "updatedAt":… }, … ] }

**注意**：网关上运行的是**独立 DSH 实例**（3099），与用户主实例（3080）**共享同一个 `~/.dsh`** —— 已实测确认两边看到同样的 12 个工作区。

**兜底**：若读 `workspace.json` 失败，**必须**回退为「按会话的 `cwd` 去重分组」，保证 App 仍可用（不得白屏）。

## 四、App 改造要求

### 4.1 导航结构
- **只保留三级**：工作区列表 → 会话列表 → 对话详情
- **移除设置页**、移除一切冗余按钮
- 返回：详情 → 会话 → 工作区

### 4.2 一级：工作区列表
- 数据源：`GET /rc/v1/workspaces`
- 每项显示：`title`（主）+ 会话数（次）
- 点击进入该工作区的会话列表

### 4.3 二级：会话列表
- 数据源：`GET /rc/v1/sessions`（按 `cwd == workspace.path` 过滤）
- 每项显示：`title`、**状态圆点**（`running` 绿 / `idle` 灰）、`messageCount`、`lastMessagePreview`
- **实时更新**：WS 推送或轮询更新 `status` / 最后消息
- 点击进入详情

### 4.4 三级：对话详情
- **历史**：`GET /sessions/{id}/messages`（倒序分页 `before`，向上加载）
- **实时**：订阅 `WS /rc/v1/stream`，新消息**追加**到末尾
- **发送**：`POST /sessions/{id}/prompt`（必须带**唯一** `requestId`，UUID）
- **停止**：运行中显示，调 `/cancel`
- **消息渲染**：
  - `role=user` 右侧；`assistant` 左侧；`tool` 折叠为 `[tool] name`；`system` 弱化样式
  - **必须支持长文本**（实测有 4600+ 消息的会话，需分页 + 虚拟列表/懒加载）

### 4.5 subagent 会话
- subagent 会话同样出现在列表中（其 `title` 形如「你是本项目的**开发工程师**…」）
- **要求**：至少能在列表中区分（如标题前加标记），点击可进入查看其对话
- **若**能拿到父子关系则嵌套显示；**拿不到就平铺**，不得因此阻塞

### 4.6 实时状态
- 会话 `running`/`idle` 变化需**及时反映**（WS 首选，轮询兜底）
- 详情页运行中时：显示停止按钮 + 流式输出

## 五、二维码与配对（回答用户问题）

### 5.1 现状（已实测）
- **生成者**：**PC 端网关**
  - `start-gateway.cmd` 启动时终端打印
  - `node print-qr.mjs` 手动生成
- **内容**：`{"v":1,"name":"…","host":"100.85.173.87","port":8765,"token":"<32hex>","fp":"<8hex>"}`
- **token**：持久化于 `pc-gateway/.state/token.txt`

### 5.2 结论：**不需要每次扫码**
token 长期有效，App 保存后自动连接。**仅三种情况需重新配对**：
1. token 轮换（`POST /rc/v1/pair/rotate`）
2. App 数据被清除（重装/换机）
3. host 变化

### 5.3 改进要求
- **PC 端**：提供一键出码（`show-qr.cmd`），终端直接显示二维码
- **App 端**：移除手动配对输入框，保留扫码；**已配对时直接进工作区列表**，不再出现配对页
- **安全**：轮换 token 后旧设备应自动失效（已有能力）

## 六、验收标准

1. App 打开后**直接进工作区列表**，数量与 PC 端一致（12 个）
2. 点任意工作区，会话数与该工作区实际一致
3. 点任意会话，能看到**历史对话**（含与 PC 端一致的末条消息）
4. **发送一条消息**，PC 端能看到；App 端能看到流式回复
5. 运行状态实时反映（PC 端发起任务时，App 列表/详情同步变化）
6. **无设置页、无冗余控件**
7. 长会话（4000+ 消息）**不卡顿、不 OOM**
8. 断网/切网后自动重连并恢复

---

## 七、约束

- 不得破坏既有契约：token 鉴权、幂等 `requestId`、5s `startForeground`、6 状态机、心跳退避、Tailscale `100.64/10` 支持
- 不引入 kapt/KSP、不新增第三方依赖（现有 CameraX/MLKit/OkHttp/Compose 可用）
- 网关改动需**保持向后兼容**（旧 App 仍可用）
